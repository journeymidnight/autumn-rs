Task scope: F147 — Three remaining snapshot-await-writeback races (sync_partition_vp_refs etcd divergence, handle_append non-batched seal recheck, run_recovery_task verify-after-fetch).

Root cause (confirmed):
  F147-A: handle_sync_partition_vp_refs applied a VP-ref diff after awaiting
  the etcd mirror without verifying that touched extents had not been mutated
  (eversion bumped, replica rewritten) during the await. On leader-failover,
  replaying the stale etcd entry produced a vp_table_refs count inconsistent
  with in-memory state, risking premature extent deletion when the diff
  under-counted retention.

  F147-B: handle_append (the non-batched path, extent_node.rs line ~2437)
  lacked the post-truncate seal recheck that F146 added to build_append_future
  (the batched handle_append_batch path). A concurrent apply_extent_meta_durable
  sealing the extent during the truncate_to_commit await allowed pwritev to land
  bytes past the new sealed_length — identical corruption to F146-HIGH-3 but on
  the non-batched code path.

  F147-C: run_recovery_task had no verify-after-fetch step. A concurrent seal
  arriving (from the manager dispatching a new eversion bump) during the
  multi-second CopyExtent fetch I/O could cause recovery to write back stale
  eversion/sealed_length metadata and log an incorrect fetch_max value. The
  recovery task would complete with CODE_OK while the extent's on-disk sidecar
  diverged from the manager's view.

Fix:
  F147-A: refuse-at-start in handle_sync_partition_vp_refs (check
  ec_conversion_inflight + recovery_tasks for every extent in the new snapshot;
  return Err(Precondition) before any await) + verify-at-apply (re-read each
  touched extent's eversion under a fresh borrow_mut after the etcd mirror;
  return Err(Precondition) if any eversion changed during the await window).

  F147-B: insert post-truncate seal recheck (sealed_length.load(SeqCst) > 0 ||
  avali.load(SeqCst) > 0) in handle_append immediately after truncate_to_commit
  returns Ok and before file_pwrite offset computation — structurally identical
  to the F146 recheck in build_append_future.

  F147-C: after sync_all following the full-extent fetch in run_recovery_task,
  re-read the local extent's eversion atomics; if it advanced during the fetch,
  return an error and trigger retry. Additionally gate the fetch_max writeback
  on the fetched length matching the manager-reported sealed_length.
