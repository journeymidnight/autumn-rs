Key findings driving the autumn-kvcache design:

  1. Interface is `HiCacheStorage` in
     python/sglang/srt/mem_cache/hicache_storage.py. Three coexisting APIs:
       - v0 (legacy, abstract methods, marked TODO Deprecate)
       - v1 (zero-copy single-pool — our main path)
       - v2 (multi-pool for Mamba/SWA/DeepSeek-V4, still evolving)

  2. Plug-in mechanism: use `dynamic` backend via
       --hicache-storage-backend dynamic
       --hicache-storage-backend-extra-config '{
           "backend_name":"autumn",
           "module_path":"autumn_kvcache.sglang_backend",
           "class_name":"AutumnKVCacheStorage",
           "interface_v1":1,
           ...
       }'
     No sglang source patch needed. `interface_v1: 1` is critical — without
     it cache_controller routes through slow v0 path.

  3. Memory model: backend NEVER sees GPU memory. It receives
     `host_indices: torch.Tensor` (page indices into pinned-host KV pool that
     it registered up-front via `register_mem_pool_host`). Block layout is
     `layer_first` (default) or `page_first*`, exposed via
     `storage_config.is_page_first_layout`.

  4. Keys are SHA-256 hex digests computed by sglang controller (Merkle-style
     chained per page). Backend must NOT hash; must add tenant suffix
     (model_name, tp_rank, tp_size, pp_rank, pp_size, is_mla_model) per
     HiCacheFile._get_suffixed_key.

  5. Concurrency: sync calls from sglang's prefetch + backup daemon threads.
     Batched per call. Prefetch budget is hard: 2s + 0.1s/Ki-tok, cap 30s.
     Slow backend → sglang abandons the request; host_indices get recycled.
     autumn-kvcache MUST return fast (success or False), never block past
     budget.

  6. Eviction: sglang NEVER calls delete. L3 must self-manage capacity
     (LRU/TTL/cap) and surface metrics via `get_stats()`.

  7. Reference backend to copy: MooncakeStore
     (python/sglang/srt/mem_cache/storage/mooncake_store/mooncake_store.py).
     Mooncake's pattern (thin Python facade over native zero-copy store, with
     `_batch_preprocess(host_indices)` translating page indices to
     (ptr, size) pairs) maps cleanly onto our planned architecture
     (ClusterClient + local DRAM cache + future peer RDMA).
     Do NOT copy LMCache pattern — it bypasses L3 abstraction entirely.

Architecture reminder (from project_three_interfaces memory, validated by
this research):
  - autumn-kvcache = sglang HiCache L3 backend (this is the API edge)
  - Internally: local DRAM LRU + peer DRAM share (future) + fall through
    to ClusterClient (partition layer) for persistence
  - Partition layer = THE distributed persistence; no parallel data plane
