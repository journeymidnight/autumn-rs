F129 Phase D — what landed in this commit:

  AutumnError extensions (crates/client/src/lib.rs):
    - 2 new variants: ValueTooLarge { size, cap } and UploadNotFound.
    - Display format omits cap when cap == 0 (server-side reject —
      we don't parse the message; client has no authoritative cap
      number to show).
    - code_to_error maps CODE_VALUE_TOO_LARGE / CODE_UPLOAD_NOT_FOUND
      to the new variants.
    - CLIENT_PUT_HARD_CAP = 256 MiB (matches PS's
      AUTUMN_PS_MAX_INLINE_BYTES_HARD).

  ClusterClient API (crates/client/src/lib.rs):
    - put_stream_begin(key, expires_at) -> PutStreamHandle. Resolves
      part_id + caches Rc<RpcClient> on the handle so subsequent
      send() calls don't re-resolve.
    - get_stream(key, chunk_size) -> Option<GetStream>. Uses head() to
      learn total_bytes upfront; subsequent next_chunk() calls walk
      the value via offset/length GetReqs.
    - Client-side cap pre-check on put_opts: rejects > 256 MiB without
      a wire round-trip; lets PS authoritatively reject 64-256 MiB
      range (default cap is 64 MiB but env-configurable).

  PutStreamHandle (handle struct):
    - send(chunk) -> bytes_committed; advances next_chunk_index.
    - commit(self) -> (); finalises the upload. Self-checks bytes_sent
      against the PS via expected_total_bytes.
    - abort(self) -> (); idempotent; best-effort RPC (no failure
      reported because PS-side TTL is the safety net).
    - Drop without commit/abort logs WARN (PS-side TTL reclaims).

  GetStream (handle struct):
    - next_chunk() -> Option<Vec<u8>>; yields chunk_size-byte chunks
      until exhausted.
    - position(), remaining(), total_bytes() accessors.

  autumn-client subcommands (crates/server/src/bin/autumn_client.rs):
    - `put-stream [--chunk-size N] <KEY> <FILE-or-->`: reads file (or
      stdin if file = "-") in chunk_size-byte chunks via PutStream API.
    - `get-stream [--chunk-size N] [--out FILE] <KEY>`: streaming read,
      writes to stdout or out file.
    - Default chunk_size is 4 MiB on both.

  Cargo.toml: added `tracing` to autumn-client's deps (used by Drop
  impl on PutStreamHandle).

Smoke test (3-replica TCP cluster, AUTUMN_PS_PARTS_HINT=8):
  - 8 MiB payload via put-stream (8×1 MiB chunks): SHA256 round-trip
    matches via both `get-stream` and regular `get`.
  - 65 MiB regular `put`: rejected with CODE_VALUE_TOO_LARGE,
    surfaced as "value 68157440 bytes exceeds the partition server's
    inline cap — use put_stream".
  - 100 MiB payload via put-stream (25×4 MiB chunks): SHA256 round-
    trip matches via `get-stream`.
  - Multiple concurrent uploads (8 MiB + 100 MiB + 100 MiB) on the
    same partition: log_stream grows to 208 MB, all reads succeed.
  - `del` on a multi-frag VP creates a tombstone; subsequent
    `head` / `get` return NotFound.
