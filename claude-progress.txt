F129 Phase B — what landed in this commit:

  PartitionData state (crates/partition-server/src/lib.rs):
    - New `UploadSession` struct: { user_key, expires_at, started_at_secs,
      last_seen_secs, bytes_committed, next_chunk_index, fragments }.
    - PartitionData gains `upload_sessions: HashMap<u128, UploadSession>`.
    - 4 caps lifted to pub(crate) so handlers can reference them:
      AUTUMN_PS_MAX_INLINE_BYTES_DEFAULT, _HARD,
      AUTUMN_PS_MAX_UPLOAD_SESSIONS_DEFAULT,
      AUTUMN_PS_UPLOAD_TTL_SECS_DEFAULT.
    - 2 op flags lifted to pub(crate): OP_VALUE_POINTER_MULTI,
      OP_CHUNK_BLOB.

  RPC handlers (crates/partition-server/src/rpc_handlers.rs):
    - handle_put_begin: TTL-evict expired sessions, check session cap,
      generate u128 upload_id from /dev/urandom, insert empty session.
    - handle_put_chunk: validate chunk_index ordering, encode V1 WAL
      record with op=OP_CHUNK_BLOB + empty key, append to log_stream,
      record (extent_id, offset+22 [V1 envelope+inner header], len)
      as a fragment on the session.
    - handle_put_commit: take session under borrow_mut, optional
      bytes-total sanity check, build MultiFragVp blob, allocate seq,
      append V1 WAL record (op=OP_VALUE_POINTER_MULTI|1, value=blob)
      to log_stream, insert MemEntry into active memtable, advance
      vp_extent_id/vp_offset, maybe_rotate.
    - handle_put_abort: idempotent session removal.
    - dispatch_partition_rpc routes the 4 new MSG_PUT_BEGIN/CHUNK/
      COMMIT/ABORT msg_types inline (NOT through merged_partition_loop;
      the per-stream worker still serialises log_stream appends).
    - handle_head fixed to report total_len for multi-frag VPs (was
      reporting blob byte-length).

  Regular Put cap reject (crates/partition-server/src/lib.rs::enqueue_put):
    - Values > AUTUMN_PS_MAX_INLINE_BYTES_DEFAULT (64 MiB) get a
      CODE_VALUE_TOO_LARGE PutResp without entering the write batch.
      Caller should retry via PutStream.

  Read side — multi-frag resolution (crates/partition-server/src/background.rs):
    - resolve_value detects OP_VALUE_POINTER_MULTI flag, decodes the
      MultiFragVp blob, calls resolve_multi_frag.
    - resolve_multi_frag walks fragments in order and reads each
      relevant slice via stream_client.read_bytes_from_extent. Reads
      are SEQUENTIAL in this v1; concurrent fan-out is F131 (deferred).

  Recovery awareness (crates/partition-server/src/lib.rs::recover_partition):
    - Skips OP_CHUNK_BLOB records (don't insert into memtable).
    - For OP_VALUE_POINTER_MULTI records, stores the blob as the
      memtable entry's value (no single-frag VP downgrade).

  Tests:
    - `enqueue_put_rejects_oversized_value`: verifies CODE_VALUE_TOO_LARGE
      reply + zero pipeline entries.
    - `enqueue_put_accepts_value_at_inline_cap`: at exactly the cap
      (NOT strictly greater) the put goes through.
    - All previous f129_multifrag_tests remain green.
    - 130/130 partition-server lib tests pass at --test-threads=1
      (was 128/128 in Phase A; +2 new).
