Design clarification from user (2026-05-09):
  - No `put_auto` / `get_auto` auto-routing. Caller explicitly picks
    `Put` (with size check; rejects > AUTUMN_PS_MAX_INLINE_BYTES with
    CODE_VALUE_TOO_LARGE) or `PutStream` (Begin/Chunk/Commit/Abort).
  - Server holds the fragment list (not client) — simpler API, < 4 KB
    per session, supports F132 resume cleanly when that's eventually
    built.
  - F134 (frame-level early reject) is deferred — separate perf
    hardening item, not part of this F129 series.

F129 Phase A — what landed in this commit:

  Wire (crates/rpc/src/partition_rpc.rs):
    - 4 new msg_type constants: MSG_PUT_BEGIN=0x49, MSG_PUT_CHUNK=0x4A,
      MSG_PUT_COMMIT=0x4B, MSG_PUT_ABORT=0x4C.
    - 2 new status codes: CODE_VALUE_TOO_LARGE=5,
      CODE_UPLOAD_NOT_FOUND=6.
    - 4 new request types + 3 new response types: PutBeginReq/Resp,
      PutChunkReq/Resp, PutCommitReq (response = PutResp),
      PutAbortReq/Resp. upload_id = u128 (16 bytes, rkyv-friendly).
    - extract_part_id() routes the new msg_types.

  Multi-frag VP (crates/partition-server/src/lib.rs):
    - 2 new op flags: OP_VALUE_POINTER_MULTI=0x40, OP_CHUNK_BLOB=0x10.
      Bit-distinct from OP_VALUE_POINTER=0x80 and from user op bits
      (1=put, 2=delete).
    - 4 new constants: AUTUMN_PS_MAX_INLINE_BYTES_DEFAULT (64 MiB),
      _HARD (256 MiB), AUTUMN_PS_MAX_UPLOAD_SESSIONS_DEFAULT (1024),
      AUTUMN_PS_UPLOAD_TTL_SECS_DEFAULT (1800s).
    - MultiFragVp struct + encode/decode (LE binary):
      `[n_frags:u32][total_len:u64][(extent_id:u64,offset:u32,len:u32) × N]`.
