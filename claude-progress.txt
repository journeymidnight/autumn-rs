TaskStatus: completed
Task scope: F-ioring-lease-3 — long-poll invalidation channel
  (manager wait-for-event hook + daemon persistent poll loop).
  Third step of the Phase 1 ioring + lease wiring (plan:
  docs/autumn_fs_lease_plan.md §4.4 / §6.4). Without long-poll the
  daemon would have to poll-spin (round-trip per second) to spot a
  writer-close on another mount; with it, manager and daemon
  coordinate via a single ~10 s long-poll that resolves in ms when
  a real event fires.

=== WHAT THIS COMMIT SHIPS ===

  - crates/manager/src/inode_lease.rs:
    - ClientInbox gains `waker: Option<oneshot::Sender<()>>`.
    - `ClientInbox::push` fires the waker when present (drop-
      replace semantics on overwrite).
    - `LeaseRegistry::drain_or_park(client)` returns
      `(events, overflowed, Option<oneshot::Receiver<()>>)` —
      atomic under one `borrow_mut`: drain returns events when
      present, else installs a fresh waker + returns the matching
      receiver.
    - 3 new unit tests: drain_or_park_returns_events_when_present,
      drain_or_park_installs_waker_and_push_wakes_it,
      drain_or_park_replaces_stale_waker.

  - crates/manager/src/rpc_handlers.rs::handle_poll_invalidations
    upgraded to long-poll. Drain immediately if events present;
    else `compio::time::sleep(LONG_POLL_WAIT=10s)` race'd against
    the waker via `futures::future::select`; on wake or timeout
    re-drain + return.

  - crates/ioring/src/bin/daemon.rs:
    - New per-session `session_invalidation_poll_loop` spawned
      next to `session_heartbeat_loop`. Tight loop over
      `lease::poll_invalidations`.
    - Per event: log WriterClosed/LeaseRevoked/MetaChanged at
      INFO (F-4 will wire the per-ino consumer that drops the
      matching `OpenedExtents`).
    - On overflow sentinel (`MetaChanged { ino=0 }` from F-1) OR
      transport error: wholesale-invalidate
      `held_leases.clear()` + `ring_fds.clear()` + best-effort
      ReleaseLease on every previously-held ino. Honours plan
      §6.4 "subscribe-disconnect = invalidate everything."
    - Transport error path sleeps 500 ms between retries (manager
      auto-reconnect via ClusterClient::mgr_call_retry covers
      reconnection).

  - crates/manager/tests/f_ioring_lease_3.rs (NEW): 3 integration
    tests against in-process AutumnManager via real ClusterClient
    transport:
      1. long_poll_returns_promptly_on_writer_close — concurrent
         writer-close after 200 ms wakes the parked reader in
         well under 2 s; ≥ 150 ms floor proves the waker actually
         waited (vs returning empty immediately).
      2. long_poll_times_out_when_idle — empty poll waits
         8 s ≤ t < 15 s then returns `Ok(vec![])`. The test takes
         ~10 s by design (this is the slow case the long-poll
         optimizes AWAY when a real event is firing).
      3. long_poll_returns_all_queued_events — two writer-closes
         on two distinct inos queued before poll both surface
         in one response.

  - crates/manager/tests/f_ioring_lease.rs: F-1's second-poll-
    empty assertion removed (with long-poll engaged, the second
    poll correctly blocks ~10 s; the "drain idempotent" property
    is now covered by `drain_or_park_*` unit tests). Single-line

  - feature_list.md: F-ioring-lease-3 in the Completed table +

=== TESTING CAVEAT ===

  Per [[reproduce_before_fixing_mechanism_bugs]] the preferred
  shape is reproduce → root-cause → fix + review. F-ioring-lease-3
  is greenfield; the 3 F-3 integration tests + 3 long-poll unit
  tests cover the wait-for-event contract end-to-end. The full
  "stale-bytes-after-close" reproducer that proves the
  invalidation actually evicts stale cache surfaces in
  F-ioring-lease-4.

  No regression was caught in F-3 development itself; the
  semantic change (poll now long-polls instead of returning empty
  immediately) needed one test update in F-1 (assertion that
  was no longer informative under the new semantics) — caught
  immediately by the 10 s test runtime, not by a wrong result.

=== NEXT SESSION HAND-OFF ===

  F-ioring-lease-4 is next + LAST in Phase 1. Outline:
    - Extend `OpenedExtents` with `(ino, version)` from the
      manager's AcquireLease response (already available as
      `MgrInodeLeaseInfo.version`).
    - In `session_invalidation_poll_loop`, on per-ino
      WriterClosed / LeaseRevoked event: drop every ring_fd
      whose `(ino, version)` is older than the event's version.
      (Don't drop newer versions — handles reorder where the
      ino was re-Open'd before the invalidation arrived.)
    - Multi-daemon e2e test: daemon A writes, daemon B opens
      + reads, daemon A closes, daemon B's NEXT Open sees the
      bumped version → cache miss → re-resolve → new bytes.
    - Consider whether `OpenedExtents.extents` (the variable-
      length extent map) needs version tagging too — yes:
      writer-close could have grown the file, so the extent
      map is stale. The Read path's `get_many_into` would
      hit ENOENT on the now-missing key. F-4 should re-run
      `fuse_read::open` (path → ino → extent map) on cache miss.

  See `docs/autumn_fs_lease_plan.md` §3.1 + §6.
