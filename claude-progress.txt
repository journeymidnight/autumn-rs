Audit verdict (after parallel 3-layer Explore + per-candidate verification):

  No new HIGH-severity unfixed races. The 12 candidates flagged by Explore agents
  resolve as follows:

  Manager: 0 candidates. Every mutating handler (handle_stream_alloc_extent /
    handle_multi_modify_split / handle_sync_partition_vp_refs / etc.) is already
    protected by the F146/F147-A refuse-at-start + verify-at-apply pattern, or
    mutates in-place inside a single borrow_mut block before any await.

  Extent-node: 5 candidates, none confirmed.
    - handle_copy_extent stale logical_len (HIGH claimed): only triggers on
      unsealed extents; production callers (run_recovery_task, handle_re_avali)
      only target sealed extents by design. → F148-B defensive guard.
    - handle_read_bytes pread stale (HIGH claimed): false — sync_all does not
      invalidate already-read user-space buffers.
    - handle_convert_to_ec idempotency (MED): already fixed by F119-D.
    - write_shard_local concurrent read (MED): false — readers go through the
      live entry.file handle, not the staging file.
    - commit_shard_local UnsafeCell swap (LOW): mitigated by single-threaded compio.

  Partition-server: 6 candidates, none confirmed.
    - F-NEW-1 PS-side sync_partition_vp_refs divergence (HIGH claimed): false —
      sync_partition_vp_refs reads p.sst_readers fresh at call time.
    - F-NEW-2 per-partition save_table_locs_raw stale-snapshot race (HIGH claimed):
      false on single-threaded compio. The path borrow_mut drop → rkyv_encode →
      stream_client.append → mpsc send is purely synchronous, so borrow_mut
      order = mpsc-send order = meta_stream record order. The latest persisted
      record's tables_snapshot necessarily reflects all prior borrow_mut
      mutations from any concurrent publisher. → F148-A inline-comment +
      regression test to lock in the invariant against future refactors.
    - F-NEW-3 compact log_extent_ids stale (MED): benign — stale snapshot
      only over-keeps discards for already-punched extents; subsequent GC
      no-ops on the missing extent.
    - F-NEW-4 split vs compaction Phase 3 (MED): closed by F140 dual-gate
      (compact_gate + gc_gate held by handle_split_part).
    - F-NEW-5 GC vs split rg narrowing (MED): closed by F140 gc_gate held
      around the entire `for eid in holes` loop including run_gc.
    - F-NEW-6 compact partial commit + crash (MED): known accepted tradeoff
      per F104 (orphan row_stream bytes; recovery loads previous checkpoint).

  Already-tracked: MED-2 (handle_get → resolve_value vs GC punch_holes) remains
  deferred as a structural feature (per-extent reader-pin protocol).

Fix shipped (F148):

  F148-A — Inline-comment + regression test for the metadata-publish ordering
  invariant. The conclusion that flush + compact concurrent publishes do not
  race is load-bearing on three properties:
    (P1) compio P-log runtime is single-threaded;
    (P2) borrow_mut blocks contain no .await;
    (P3) the path borrow_mut drop → rkyv_encode → stream_client.append →
         mpsc-send-into-per-stream-worker is purely synchronous; first .await
         is on the per-stream worker's ack_rx (after FIFO mpsc).
  Inline `// F148-A invariant` comments at flush_one_imm + flush_one_imm_local
  (lib.rs) and both branches of do_compact (background.rs) state the rule next
  to the code. New test
  f148_publisher_invariant_tests::f148_concurrent_publisher_ordering_invariant
  exercises two simulated publishers on one compio runtime via futures::join!
  and asserts:
    (A1) worker received both publishes;
    (A2) the LATER publisher's snapshot includes the EARLIER's mutation;
    (A3) the LATEST received snapshot equals the post-state of shared tables.

  F148-B — Defensive guard in handle_copy_extent (extent_node.rs). After
  manager-fetch + apply_extent_meta_durable, refuse with CODE_PRECONDITION
  when entry.sealed_length == 0. Production callers only target sealed extents,
  so this is belt-and-braces — converts a theoretical race window (where a
  stray caller could observe a mix of pre- and post-truncate-to-commit bytes
  via file_pread_chunked on an unsealed extent) into a clean error.
