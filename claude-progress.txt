Task scope: F130 — GC active rewrite for multi-fragment ValuePointers.
            Closes the F129 sustained-use disk-leak gap: without F130
            the existing single-VP GC pass skipped OP_CHUNK_BLOB
            records (correctly — those are bare byte blobs, not WAL
            entries), and `punch_holes` would orphan live multi-frag
            chunks on the reclaimed extent.

Approach:
  - **Full-value rewrite** when GC targets an extent with any chunk
    of any live multi-frag value: rewrite the ENTIRE multi-frag value
    (every fragment, even those on extents other than the one being
    reclaimed) to the active log_stream tail. Avoids the partial-
    overlap discard accounting bug that selective rewrite would
    introduce — when compaction later shadows the old mfvp, it can
    blindly bump per-extent discards for every frag.
  - **MVCC seq ordering** for race safety: rewrite allocates a fresh
    seq under brief borrow_mut. A foreground Put on the same user_key
    always gets a strictly newer seq and shadows the rewrite via the
    inverted-seq byte ordering of internal_keys. Rewrite chunks
    become orphan if foreground wins; next GC pass collects them.
    Same pattern as the existing single-VP process_gc_chunk.
  - **No procedure-WAL needed**: the design is per-extent and idempotent;
    a PS crash mid-rewrite leaves orphan OP_CHUNK_BLOB records on the
    new tail and the original mfvp still pointing at the old extent
    — recovery just sees both, MVCC picks the right one.

Implementation:
  - `bump_discards_for_dropped_entry(discards, op, raw_value)` —
    helper extracted from 4 sites in `do_compact`'s drop branches
    (dedup, range filter, tombstone, expired). Now handles BOTH
    single-VP (existing) and multi-frag VP (new): for multi-frag,
    decodes MultiFragVp and bumps per-extent discards for EVERY
    fragment.
  - `collect_live_mfvps_touching(part, eid)` — walks active memtable
    + imm queue, dedups by user_key (newest wins), returns mfvps with
    at least one fragment on the to-be-reclaimed extent.
  - `rewrite_multi_frag_for_extent(part, log_stream_id, eid, part_sc)`
    — main rewrite loop. Per candidate:
      1. Read every fragment via read_bytes_from_extent.
      2. Append each as a fresh OP_CHUNK_BLOB record.
      3. Build new MultiFragVp.
      4. Allocate seq under borrow_mut.
      5. Append OP_VALUE_POINTER_MULTI|1 commit record.
      6. Insert memtable entry, update vp_extent_id / vp_offset.
  - `run_gc` calls `rewrite_multi_frag_for_extent` as a pre-pass
    BEFORE the existing single-VP `process_gc_chunk` loop. After the
    pre-pass, the single-VP scan can punch_holes safely.

Scope limitation (recorded in feature_list F130 + CLAUDE.md):
  - Pre-pass walks active memtable + imm only, NOT SSTs. Live mfvps
    whose newest copy is only in an SST and not yet shadowed are
    handled by the compaction discard path: compaction shadows the
    SST entry → bumps discards for every frag → host extents
    eventually accumulate > 40% discard ratio → next GC tick picks
    them.
  - This trade-off avoids walking every entry of every SST on every
    GC tick (O(SST bytes) per tick). If production sees stuck
    extents that compaction takes too long to clear, add a targeted
    scan via the existing SST `vp_deps` index.
