Task scope: F204 — stale-VP read error attribution. Surface
            pre-2026-04-27 historical corruption signals via a
            structured sentinel error so external Python operational
            tooling can distinguish "data permanently lost; clean
            up the key" from transient server errors.

User-reported symptom (the bug we attribute, not fix):
  $AC get Patreon--leeesovely-October-2024-MissKON.com-054.jpg
  Error: get: connection error: rpc status Internal:
  ec_read_full_and_slice: offset 264784123 past decoded payload
    len 11570792 (requested length=10918365) for extent 29
    (manager sealed_length=11570792)

  - The VP in some SST points (extent_id=29, offset=264MB, len=10MB)
  - Manager records extent 29 sealed_length=11.5 MB
  - On-disk EC shards physically encode 11.5 MB; bytes past it
    do not exist anywhere
  - Pre-2026-04-27 handle_stream_alloc_extent x EC convert race
    shrunk sealed_length from the original (likely 34.7 MB) down
    to shard_size (11.5 MB); F119-D double-encode then physically
    rewrote shards to the sub-size
  - All write-side fix paths are deployed (F138/F145/F146/F147/F149
    + the 2026-04-27 `tail.sealed_length > 0` guard); etcd state
    from the pre-fix era persists and cannot be self-detected

Decisions:

  - Surface, don't repair. Manager has no "previous correct value"
    to compare against; SSTs are immutable; physical shards are
    truncated. Cleanup must be OP-driven.
  - No `client audit-vps` CLI (user preference: ops tools in
    Python, not autumn-client). Saved to memory:
    feedback-ops-tools-in-python.
  - No open-time integrity scan (too slow).
  - No replay_from_etcd warn (no reliable suspect signal).
  - No extent-node-side monotonic guard (manager-side already
    guarded; extent-node guard is speculative).

Implementation:

  1. crates/stream/src/client.rs:
     - new `pub struct StaleVpOffset { extent_id, requested_offset,
       requested_length, sealed_length }` sentinel + Display +
       std::error::Error impls. Display contract is a STABLE wire
       protocol:
         stale_vp_offset_past_sealed_length: extent=<EID> offset=<OFF>
         length=<LEN> sealed_length=<SEAL>
       Python tooling regex consumers MUST treat the prefix and
       4-field order as load-bearing.
     - `ec_slice_decoded(payload, offset, length)` ->
       `ec_slice_decoded(payload, offset, length, extent_id, sealed_length)`.
       Out-of-bounds branch now returns
       `Err(anyhow::Error::new(StaleVpOffset { ... }))` instead of
       a stringy `anyhow!(...)`.
     - `ec_read_full_and_slice` drops its outer
       `anyhow!("ec_read_full_and_slice: ...")` wrap; the sentinel
       surfaces unmodified through the chain.
     - test mod ec_slice_tests updated:
       slice_offset_past_end_returns_err_not_panic asserts the
       error chain contains StaleVpOffset with all 4 fields
       correct and the Display prefix.

  2. crates/stream/src/lib.rs:
     - `pub use client::StaleVpOffset` for downstream consumption.
