=== WHAT THIS COMMIT SHIPS ===

  - crates/ioring/src/header.rs: RING_VERSION 1 → 2; new
    CAP_INODE_LEASE flag; default capabilities updated.

  - crates/ioring/src/sqe.rs: `Sqe` gains `lease_mode: u8` carried
    in the flags byte. Decode accepts {0,1,2} for Opcode::Open
    (0 ⇒ daemon defaults to WRITE, the safe upper bound); preserves
    the pre-v2 "flags=0 for every other opcode" invariant. Three
    new tests: round-trip read+write modes, invalid lease-mode
    rejected, non-Open opcodes still reject any non-zero flag.

  - crates/ioring/src/lease.rs (NEW): typed daemon-side wrappers
    for the four MSG_*_LEASE RPCs. `DaemonClientId` (UUID-backed
    MgrClientId, kind=IORING). `acquire / release / heartbeat /
    poll_invalidations` over `ClusterClient::mgr_call_retry`.
    Errors classified `Conflict / NotLeader / Manager / Transport`
    for the daemon to map to errno (CONFLICT → EBUSY; anything
    else → EIO).

  - crates/ioring/src/bin/daemon.rs: per-session `Rc<DaemonClientId>`
    + per-inode refcounted `held_leases: HashMap<u64, SessionLease>`.
    Open: refcount→1 ⇒ AcquireLease, EBUSY on Conflict, EIO on
    transport; refcount>1 ⇒ share (mode-pinned at first Open;
    mismatched-mode 2nd Open ⇒ EBUSY — no silent upgrade/downgrade).
    Close: refcount→0 ⇒ ReleaseLease; warn-on-error (manager TTL
    revoke is the backstop). New per-session
    `session_heartbeat_loop` (5 s tick, TTL/6 safety factor) renews
    every held inode; `NotHeld` ⇒ drop the entry + evict every
    ring_fd backed by it (subsequent ops → EBADF — explicit failure
    beats silently serving stale state).

  - crates/ioring/src/bin/bench.rs: read-only bench sets
    `lease_mode = SQE_LEASE_MODE_READ` so multiple bench instances
    can share the same hot file.

  - crates/ioring/src/ring.rs: test helper `dummy_sqe` updated for
    the new field.

  - crates/manager/src/inode_lease.rs: REGRESSION fix discovered by
    F-ioring-lease-2 integration test
    `writer_release_unblocks_second_daemon_and_bumps_version`.
    Pre-fix, the auto-remove of an empty inode entry on release
    reset `version` to 1 — a fresh acquire then handed out
    `(ino, version=1)` which collides with a pre-existing reader
    cache from the prior generation, silently breaking close-to-
    open coherence. Fix: `LeaseRegistry.last_version` shadow
    persists the high-water mark across remove/re-create; every
    `release / tick / acquire / install_persisted_writer` calls
    `remember_version(ino, version)`; `inode_or_create` seeds new
    entries from the shadow. Covered by new unit test
    `version_is_monotonic_across_remove_and_reacquire`.

  - crates/ioring/Cargo.toml: `uuid` workspace dep added under the
    `daemon` feature (used by `DaemonClientId::new`).

  - crates/manager/tests/f_ioring_lease_2.rs (NEW): 4 integration
    tests that drive `autumn_ioring::lease::*` against an in-
    process AutumnManager via the real ClusterClient transport:
      1. Two daemons writing same ino → second returns Conflict
         (this is what the daemon maps to libc::EBUSY).
      2. Two daemons reading same ino → both Granted (read-read
         no-conflict).
      3. Writer release unblocks 2nd daemon AND version monotonic
         across the remove/re-create boundary (caught the
         last_version shadow bug).
      4. Heartbeat returns Renewed on a held lease and NotHeld
         post-release (the path session_heartbeat_loop uses).

  - feature_list.md: F-ioring-lease-2 in the Completed table +
    detail section under P14 (10 invariants now, L1–L11 spanning
    F-1 + F-2).

  - crates/manager/CLAUDE.md: Programming Note 34 extended with
    L11 (version monotonic across inode entry lifetime).

  - README.md: F-ioring-lease bridge updated — manager-side AND
    daemon-side smoke tests, plus a manual daemon exercise script.

=== TESTING CAVEAT ===

  Per [[reproduce_before_fixing_mechanism_bugs]] the preferred
  shape is reproduce → root-cause → fix + review. F-ioring-lease-2
  is greenfield wiring; the 4 F-2 integration tests + new
  monotonicity regression test cover the contract surface. The
  REAL failure mode (two daemons with stale caches reading
  divergent bytes) surfaces only when F-ioring-lease-4's full e2e
  lands (real ring buffers + version-tagged OpenedExtents +
  invalidation push).

  The `last_version` monotonicity fix WAS triggered by an actual
  test failure ("left: 1, right: 2"), not a code-review finding —
  exactly the order the regression rule prefers (reproduce first,
  fix second). Documenting it because the failure was caught by
  the F-2 integration test, not by a chaos run.

=== NEXT SESSION HAND-OFF ===

  F-ioring-lease-3 is next. Outline:
    - Manager-side: add a wait-for-event hook on
      MSG_POLL_INVALIDATIONS. When a client polls and its inbox is
      empty, register a oneshot waker; subsequent push_invalidation
      fires the waker so the next poll resolves immediately. Hard
      cap on the wait (~10 s) so an idle connection still
      heartbeats. Implementation: extend `ClientInbox` with
      `waker: Option<oneshot::Sender<()>>`.
    - Daemon-side: spawn a per-session `invalidation_poll_loop`
      that calls `lease::poll_invalidations` in a tight loop. On
      transport error → drop ALL cached ring_fds (plan §6.4:
      subscribe-disconnect = invalidate everything). On
      LEASE_INVAL_META_CHANGED with ino=0 (overflow sentinel
      F-ioring-lease-1 ships) → same wholesale invalidation.
    - F-3 doesn't yet act on per-ino invalidations beyond logging;
      F-4 wires the version-tagged cache that actually consumes
      `(ino, version)` from the push.

  See `docs/autumn_fs_lease_plan.md` §4.4 + §6.4 for the
  long-poll vs streaming-RPC decision (we picked long-poll).
