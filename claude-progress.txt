Audit (verified 7 surfaces):
  Hot-path binary RPC frames (Append/ReadBytes/CommitLength) decode
  by hand without rkyv bytecheck (F155 covered control plane only)
  and have no application-level CRC. TCP CRC catches most network
  corruption but leaks ~1 in 10⁸–10¹⁰ corrupt segments past
  detection (Stone & Partridge 2000); TX/RX checksum offload bugs
  in NIC drivers can present uncorrected bytes. A flipped bit in
  AppendReq's `extent_id`/`eversion`/`commit`/`revision` would be
  silently trusted by `handle_append`'s decoder.

  Verified surfaces (all in crates/stream/src/extent_rpc.rs +
  crates/rpc/src/frame.rs):
    1. AppendReq header (HIGH): wrong extent / fence bypass / data loss
    2. AppendReq payload (HIGH): wrong bytes written + ack'd
    3. ReadBytesResp payload (HIGH): wrong bytes returned to client
    4. CommitLengthResp.length (MED): consensus min poisoned
    5. Frame payload_len (MED): hang / OOM on bound-less reader
    6. AppendReq eversion check race (MED): stale eversion accepted
    7. CommitLengthResp.code (LOW): false success with poisoned length

Design (per-frame CRC32C V1 wire format):
  V0 frame: [req_id 4][msg_type 1][flags 1][payload_len 4][payload N]
  V1 frame: [req_id 4][msg_type 1][flags|FLAG_CRC 1][payload_len=N+4][payload N][crc32c 4]
  FLAG_CRC = 0x08 (free in current flags byte). Decoder dispatches:
  V1 → verify CRC + strip trailer; V0 → legacy. Backward-compatible.
