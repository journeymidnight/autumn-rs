=== ROOT CAUSE (proved by code inspection + on-disk forensics) ===

  Site: crates/partition-server/src/lib.rs::flush_one_imm

  `flush_one_imm` returns Ok(false) in TWO different cases:
    (a) `imm` queue is empty — drain genuinely done.
    (b) `imm[0]` is already claimed by background_flush_loop
        (its ptr lives in `flushing_imm_ptrs`) — flush still in
        progress; row_stream.append has NOT yet ACKed.

  Three callers loop `flush_one_imm` and break on the first
  Ok(false), conflating (a) and (b):
    - flush_memtable_locked     (lib.rs:6702)  → maintenance FLUSH
    - try_complete_freeze_drain (lib.rs:5024)  → split / merge freeze
    - graceful-shutdown drain    (lib.rs:4980)

  Concrete failure mode (matched by the on-disk state):
    1. Memtable rotates to imm. background_flush_loop claims imm[0],
       fires P-bulk row_stream.append. ptr inserted into
       flushing_imm_ptrs.
    2. Split RPC arrives. handle_split_part sets `frozen_for_split`,
       partition_loop runs try_complete_freeze_drain.
    3. Drain calls flush_one_imm → sees imm[0] already claimed by
       bg flush → returns Ok(false) → drain loop breaks. drain_ack
       sent.
    4. handle_split_part calls part_sc.commit_length(row_stream).
       row_stream's `last_synced` on EN replicas does NOT yet cover
       the in-flight SST upload. commit_length returns the
       pre-flush durable length (19678).
    5. multi_modify_split fires with row_sealed_len=19678.
       compute_duplicate_stream seals extent 12 at sealed_length=19678
       in manager etcd, bumps eversion.
    6. Background flush completes its row_stream.append: SST bytes
       up to 28258 land all-replica-acked. P-log atomically pushes
       new TableMeta + save_table_locs_raw writes TableLocations to
       meta_stream referencing offsets 23838 + 26438 (past 19678).
    7. Stream worker's invalidate_stream landed at split, but the
       in-flight worker's cached eversion=1 is what wrote those
       bytes — EN-side eversion stays 1, .meta sealed=0, file=28258
       bytes (verified from /tmp/autumn-rs/d{2,3,4}/3d/extent-12.{dat,meta}).
    8. On next PS open, recover_partition reads metaStream
       TableLocations, hits read_bytes_from_extent at (12, 26438, 1820),
       StreamClient sees ExtentInfo.sealed_length=19678 < 26438+1820,
       returns the structured StaleVpOffset sentinel. Partition is
       permanently unopenable.

  Forensics summary (extent 12):
    Manager etcd:      sealed=true, sealed_length=19678, eversion=5
    EN .meta (V2):     sealed=false, sealed_length=0,  eversion=1
    Physical file:     28258 bytes on all 3 replicas
    Affected parts:    15 (rowStream 11=[12,37]), 29 (rs=27=[12]),
                       34 (rs=32=[12])
    Partition 24 (rs=22=[12]) opens fine because its commit_length
    matches sealed_length exactly.

=== FIX (shipped) ===

  Patch: crates/partition-server/src/lib.rs

  1. New helper `await_imm_fully_drained(part)` polls every 2 ms
     until `imm.is_empty() && flushing_imm_ptrs.is_empty()`. Caller
     contract is that the caller holds the freeze/shutdown flag so
     no new imm can appear during the wait — drain is monotonic.

  2. `flush_memtable_locked` / `try_complete_freeze_drain` /
     graceful-drain on Ok(false): re-check
     `imm.is_empty() && flushing_imm_ptrs.is_empty()`. If truly
     done, break. Otherwise sleep 2 ms and continue. Defensive
     `await_imm_fully_drained` at the very end as a sentinel
     against future regressions.

  Build: `cargo build -p autumn-partition-server` PASSES.
