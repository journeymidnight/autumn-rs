F210-E sub-features:
  E1 — handle_re_avali replicated path acquires concurrency permit
       - crates/stream/src/extent_node.rs (handle_re_avali)
       - Hooks `acquire_recovery()` AFTER the EC short-circuit + the
         already-up-to-date check and BEFORE
         `fetch_full_extent_from_sources`. RAII permit held for the
         remainder of the replicated repair path. Same shared pool
         as `run_recovery_task` (default 2, env
         AUTUMN_EXTENT_RECOVERY_PARALLELISM).

  E2 — Defensive auto-compact for SST count runaway
       - crates/partition-server/src/background.rs
       - New `MAX_SST_BEFORE_AUTO_COMPACT = 32` const. The
         compact loop's timeout arm calls `pickup_tables` +
         `do_compact(major=false)` when `sst_readers.len() >`
         the threshold AND `compact_inflight == 0`. Threshold
         picked to keep the 1% per-SST bloom FPR's cumulative
         miss-path false-positive bounded (≤ 28% at N=32 vs 63%
         at N=100). Mechanism-level defensive bound — not a
         policy knob; not env-tunable.

  E3 — compute_ec_advisory per-tick cap
       - crates/manager/src/policy.rs (compute_ec_advisory)
       - New `MAX_EC_ADVISORY_CANDIDATES = 256` const. Sorts by
         sealed_length desc + truncates after collection. Caps
         the advisory_cache + MSG_GET_POLICY_CANDIDATES payload
         at ~1 MiB to stay under etcd's max-request-bytes.

F210-F sub-features:
  F1 — Freeze policy kind enum + const-dump RPC
       - crates/rpc/src/manager_rpc.rs:
         + WIRE-STABILITY docstring above the POLICY_KIND_*
           block: numeric values frozen, new kinds APPEND only.
         + New `MSG_GET_POLICY_KIND_NAMES = 0x3B` const-dump RPC.
         + `policy_kind_names()` helper returning a Vec of
           (String, u8) pairs.
       - crates/manager/src/rpc_handlers.rs: dispatch +
         `handle_get_policy_kind_names` (no leader gate — the
         answer is a compile-time constant of THIS binary).

  F2 — Sustained N buckets actually means N × bucket_sec
       - crates/manager/src/policy.rs:
         `PartitionMetricsWindow::push_with_cap_and_bucket`
         snaps incoming ts to bucket_sec boundary; same bucket
         as previous → REPLACE (last-wins within a bucket).
         Pre-F210-F2 every PS 5 s report became its own bucket;
         required_buckets=5 represented 25 s, not 5 min.

  F3 — Metrics freshness + ownership prune
       - crates/manager/src/policy.rs: new
         `PolicyEngine::prune_stale_metrics(state, now)`.
       - crates/manager/src/lib.rs (policy_tick_loop): call at
         top of tick BEFORE compute_*_advisory.
       - Drops metrics for partitions no longer in state.partitions;
         drops windows whose latest bucket is older than
         STALE_METRICS_AGE_SEC = 300; prunes last_hot_cold_at for
         evicted PSes.

  F4 — Hot/cold same-partition band guard
       - crates/manager/src/policy.rs (compute_hot_cold_advisory)
       - New `HOT_COLD_BAND_DIVISOR = 2` const. A partition
         qualifies as hot only when its min ≥ qps_hottest / D;
         cold only when its max ≤ qps_coldest * D. Same on size.
         Empty band → suppress dimension. Closes the "rotating
         hotspot appears on BOTH lists" case.

  F5 — PolicyConfig.window_buckets becomes load-bearing
       - crates/manager/src/rpc_handlers.rs
         (handle_report_partition_load) now reads
         `p.config.window_buckets / p.config.bucket_sec` and
         calls `push_with_cap_and_bucket` instead of the
         hardcoded `push`. set_policy_config now reshapes the
         history window at runtime.

  F6 — handle_get_policy_candidates leader gate
       - crates/manager/src/rpc_handlers.rs
       - Mirrors F209-A's pattern. Returns CODE_NOT_LEADER +
         empty `candidates` Vec when not leader.

F210-G sub-features:
  G1 — PS eviction etcd mirror + heartbeat seed on replay
       - crates/manager/src/lib.rs:
         + ps_liveness_check_loop now explicitly DELETEs
           `psNodes/<evicted_id>` via fenced put_and_delete_txn
           before mirror_partition_snapshot.
         + replay_from_etcd seeds
           `ps_last_heartbeat[ps_id] = Instant::now()` for every
           replayed PS so the liveness loop's `Some(t)` arm
           engages after PS_DEAD_TIMEOUT.
       - Together (1) prevents etcd resurrection of the dead PS
         and (2) hands every replayed PS one fresh eviction
         window. The pre-F210-G1 None-arm-as-alive bug is now
         unreachable.

  G2 — Persisted retry queue for budget-exhausted deletes
       - crates/manager/src/extent_delete.rs: new
         `MgrExtentDeleteRetry` rkyv struct, new
         `EXTENT_DELETE_RETRY_PREFIX = "extentDeleteRetry/"`,
         new `persist_failed_delete()` +
         `extent_delete_retry_loop()`. Exponential backoff
         (60 s base, 1 hr ceiling, 2× per attempt up to 6 shifts).
       - crates/manager/src/lib.rs: new `failed_deletes` field
         on AutumnManager; replay_from_etcd rehydrates from the
         prefix; start_runtime_tasks spawns the retry loop.
       - The inflight ledger Delete marker is still RELEASED
         when the entry moves to the persisted retry queue (so
         future ops on the extent aren't blocked) — the retry
         queue is orthogonal etcd state.

F210-H sub-features:
  H1 — Replicated read stale-VP sentinel
       - crates/stream/src/client.rs (read_with_layout)
       - Upfront check at top of read_with_layout: if
         `ex.sealed_length > 0 && offset > ex.sealed_length`,
         construct and return `StaleVpOffset { extent_id,
         requested_offset, requested_length, sealed_length }`
         BEFORE branching on `ex.ec_converted`. Covers both
         replicated and EC paths uniformly; EC's
         ec_slice_decoded retains its own check as
         defense-in-depth. Skips the wasted server round-trip +
         EC decode on a known-stale VP. Operational tooling's
         `stale_vp_offset_past_sealed_length:` regex now fires
         on replicated cases too.
