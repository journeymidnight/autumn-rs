Main gaps (NOT done — next session):
  1. PS <- EN hop (#9/#10) — the EN->PS value copy is still present. Design
     decided but DELIBERATELY not rushed: a naive call_into_dest into a
     caller-owned dest is NOT cancel-safe on this path because the EN read
     uses a 3 s timeout + replica failover. If the call times out / a
     replica is dropped, the multiplexed read_loop (separate task) can
     still write into a dest the caller has freed (use-after-free). The
     client <- PS hop avoids this (no timeout; the sglang page outlives the
     call). The SAFE design for PS <- EN: the read_loop OWNS a RegPool
     PooledBuf, recvs into it, and hands the PooledBuf back via the meta
     channel; on caller-cancel the read_loop drains into the pool buf and
     returns it to the pool (no UAF). Then EN gets a new additive
     MSG_READ_BYTES_ZC that emits a V0 frame [zc_meta:9][value] as 2 Bytes
     (also removes the EN-side ReadBytesResp.encode()+Frame::encode() double
     value copy); StreamClient gets a read-into-pooled fast path for the
     replicated, single-chunk, non-EC case (EC / chunked / failover-exhaust
     fall back to the untouched copy path); resolve_value returns the
     PooledBuf; handle_get_zc sends it to the client (no first-cut concat).
