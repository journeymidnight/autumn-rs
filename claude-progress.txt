Architectural context:
  - User architectural review after F206 (avali bug): EC convert had
    accumulated 13 F-numbers of mutex / inflight bookkeeping bugs.
    User asked whether moving coordinator from EN to manager would
    help. Conclusion: no — violates control/data-plane separation,
    multiplies network 2.5x, only eliminates 2 of 13 bug classes.
  - Real lever: 5 of those bug classes (F126/F138/F139/F145/F147-A)
    are the same "if-extent-in-set then refuse" pattern done five
    times across 4 scattered inflight mechanisms. F207 collapses
    them into one etcd-backed ledger.
  - Layer boundary correction (user): split/merge are PS-layer
    (partition-scoped), not stream-layer. The ledger is a stream-
    layer concept covering ConvertToEc / Recovery / Delete only.
    PS-layer handlers READ the ledger but do not enroll.
  - PS-layer ↔ stream-layer interaction: three classes (A/B/C)
    handled by refuse-at-start / verify-at-apply (F146 pattern) /
    exclusive CAS — composes via asymmetric read/write
    responsibilities.

What F207-A specifically did:
  1. NEW crates/manager/src/extent_inflight.rs (~370 lines incl.
     tests). Types:
       - MgrExtentInflightRecord (flat-struct on-disk shape with
         op_kind byte + three Option payloads, exactly one Some by
         invariant — avoids being the proving ground for rkyv 0.8
         enum CheckBytes support).
       - ExtentOpKind discriminator (ConvertToEc / Recovery / Delete).
       - ExtentOpPayload typed view enum (Rust-only, not rkyv).
       - PersistedPendingDelete (drops the in-memory `attempts`
         counter from the existing PendingDelete).
     APIs:
       - acquire_extent_inflight: CAS via create_revision==0 +
         F149 leader fence (txn_fenced).
       - build_extent_inflight_release_op: returns the etcd delete
         Op for caller to bundle into its own apply-done txn (I3).
       - commit_extent_inflight_release: in-memory cleanup.
       - extent_inflight_op: read-only probe.
       - decode_extent_inflight_kvs: replay-time decoder that drops
         malformed records with WARN.
  2. crates/manager/src/lib.rs:
       - `mod extent_inflight;` declaration.
       - `inflight: Rc<RefCell<HashMap<u64,
         MgrExtentInflightRecord>>>` field on AutumnManager.
       - Initialised in `new()`.
       - Replay arm added to `replay_from_etcd` for the
         `extent_inflight/` etcd prefix. Empty on pre-F207 clusters.
