set-stream-ec specifically (asked by user):
  - Kept. Post-F203 it only mutates MgrStreamInfo.ec_data_shard /
    ec_parity_shard; dispatch loop is drain-only so it does NOT
    auto-convert anything anymore.
  - handle_force_ec_convert rejects extents on replicates-only
    streams with CODE_PRECONDITION ("set-stream-ec first").
    compute_ec_advisory (F202) also filters them out.
  - Therefore set-stream-ec is the prerequisite primitive to flip
    a stream from replicates-only -> EC-eligible. The OP toolkit
    workflow is: set-stream-ec --stream X --ec K+M, then for each
    sealed extent on X that's not converted yet, force-ec-convert
    --extent EID. Both are mechanism primitives consumed by a
    Python controller, not by the manager kernel.
  - Without set-stream-ec, the only path to EC would be
    bootstrap-time `--log-ec` / `--row-ec`. Upgrading an existing
    replicates-only stream to EC after cluster lifetime would be
    impossible. Rare scenario but irreversible-on-removal.

Migration UX:
  - `info --top N` -> exits with code 2 + message pointing to jq.
  - `streams` -> "unknown command"; user runs
    `info --json | jq '.streams'`.
  - `streamput` -> "unknown command"; user runs `put-stream`.
