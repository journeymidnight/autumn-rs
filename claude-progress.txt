Task scope: F185 — Manager-orchestrated partition merge with PS freeze-drain.
            Closes the F184-K ~5% merge-window data-loss gap at 0 loss.

Approach chosen (TiKV PrepareMerge model, NOT spec §4.1's PS-orchestrated
4-gate cross-thread design):
  - Leader-fenced control plane (manager) is the orchestrator
  - CLI is a thin wrapper around one new RPC: MSG_MERGE_PARTITIONS
  - PSes self-freeze in-place via MSG_MERGE_FREEZE — no cross-thread channels
  - In-memory splice (spec §4.1) NOT done — survivor reopens via existing
    region_sync_loop reload (F184-B) + read_all_table_locations union (F184-C)
  - Trade-off: merge wallclock stays ~2-3 s (vs spec's <1 s); data loss → 0
  - Crash safety via FREEZE_TTL = 30 s backstop on PS, no procedure-WAL

Wire additions:
  - partition_rpc: MSG_MERGE_FREEZE = 0x4E, MergeFreezeReq/Resp,
                   CODE_UNAVAILABLE = 7
  - manager_rpc:   MSG_MERGE_PARTITIONS = 0x37, MergePartitionsReq/Resp

PartitionData state:
  - frozen_for_merge: Cell<Option<Instant>>     — Some(set_at) while frozen
  - freeze_drain_ack: RefCell<Option<oneshot>>  — parked freeze response

merged_partition_loop changes:
  - top-of-loop freeze drain check: rotate active + flush_one_imm in a
    loop; once pending+inflight both empty, send OK on parked ack
  - top-of-loop FREEZE_TTL check: auto-unfreeze on 30 s expiry,
    surface PRECONDITION error to any stale ack
  - handle_incoming_req: Put/Delete/StreamPut return CODE_UNAVAILABLE
    while frozen; reads/maintenance still flow
  - handle_incoming_req intercepts MSG_MERGE_FREEZE inline:
      freeze=true:  set frozen + park resp_tx in freeze_drain_ack
      freeze=false: clear frozen, ack OK immediately
  - idempotency: re-freezing already-drained partition replies OK;
    second freeze while drain pending replies PRECONDITION

handle_merge_partitions (manager, new):
  1. ensure_leader + resolve part_addr / stream ids in one borrow
  2. acquire admin owner-lock for the partition pair
  3. MSG_MERGE_FREEZE → victim PS, await OK (drains+flushes)
  4. MSG_MERGE_FREEZE → survivor PS, await OK
  5. capture commit_length × 6 via handle_check_commit_length
  6. handle_multi_modify_merge synchronously (existing F183 logic)
  7a. on OK: leave PSes frozen (region_sync_loop drops them on next tick)
  7b. on err: best-effort MSG_MERGE_FREEZE freeze=false rollback to all
