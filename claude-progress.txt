Summary:
  Implemented autumn-kvcache as a thin Python adapter (`python/autumn_kvcache/`)
  layered over the existing `autumn` PyO3 client. No new Rust crate, no
  sidecar daemon, no local DRAM LRU — partition layer's memtable + block
  cache serves as the implicit DRAM tier.

  Design convergence is documented in `docs/autumn_kvcache_plan.md`
  (written this session). The earlier F216 entry that called for a
  `crates/kvcache/` Rust crate + local DRAM LRU was rewritten to match
  the new design: deployment is single-sglang-per-node (possibly
  multi-node via TP/PP), so the daemon's only justification (cross-
  process same-node sharing) does not apply.

Architecture invariants enforced:
  - All persistence via `autumn-client` → partition layer (no parallel
    data plane, [[feedback_no_parallel_data_plane]]).
  - No sglang-side delete is ever issued — sglang never calls delete on
    L3; capacity is partition TTL/GC's job (autumn-kvcache surfaces
    nothing).
  - Backend returns fast: `False` on miss, exception on RPC error;
    never blocks past sglang's prefetch budget (2s + 0.1s/Kitok).
  - Idempotent put: same key/value re-set is a no-op.
