Task scope: F171 — Structural migration of `ExtentEntry.file` from
            `UnsafeCell<CompioFile>` to `RefCell<Rc<CompioFile>>`.
            Closes the type-level UB at the file-replacement path
            (line 2378, ex-2314 EC commit) by making the replace path
            return the OLD `Rc` to be dropped only after concurrent
            readers release their clones. Completes the F166/F167
            line of work — there is now zero `unsafe` and zero
            `UnsafeCell` in any file-access path on the extent node.

Why:
  F166 fixed `&mut` aliasing UB on borrow paths (file_pwrite,
  build_append_future) by switching to shared `&File`. F167
  encapsulated the file-REPLACE path with a documented `unsafe fn
  replace_file_under_lock`, but the type-level UB remained: a
  concurrent reader holding `&CompioFile` from `unsafe { &*file.get() }`
  is dangling if `replace` fires mid-read. F119-C's eversion-mismatch
  reject blocked it in practice; F171 closes it at the type level so
  no future contributor can reintroduce the pattern at a new call site.

How:
  Field type: UnsafeCell<CompioFile> → RefCell<Rc<CompioFile>>.

  New methods on ExtentEntry:
    fn file_rc(&self) -> Rc<CompioFile>      // brief borrow + clone
    fn replace_file(&self, new: CompioFile)  // safe borrow_mut + swap

  All 5 file helpers (file_pwrite, file_pread, file_pwrite_chunked,
  file_pread_chunked, plus the chunk-loop's per-iteration calls) take
  `Rc<CompioFile>` by value. The future captures it, deref gives
  `&CompioFile` for the syscall. RefCell borrow is released before
  the first .await.

  Free function `file_ref` deleted — callers use `entry.file_rc()`
  directly. The Rc deref handles `.sync_data().await`,
  `.metadata().await`, `.estimated_size()` etc identically to the
  prior `&CompioFile`.

  Construction sites:
    3× `ExtentEntry { file: UnsafeCell::new(file), .. }`
       → `ExtentEntry { file: RefCell::new(Rc::new(file)), .. }`
    1× `staging_cell = UnsafeCell::new(staging_file)` in
       `prepare_shard_local` (local-only, never aliased)
       → plain `Rc::new(staging_file)`

  Replace site (commit_shard_local, ex-line 2378):
    `unsafe { entry.replace_file_under_lock(new_file); }`
    → `entry.replace_file(new_file);`

What's no longer load-bearing:
  - F153 per-extent ec_conversion_locks: still serialises concurrent
    EC dispatches racing on the staging path, but no longer the sole
    memory-safety guarantor for the file replace.
  - F119-C eversion-mismatch reject: belt-and-braces for client-side
    cache freshness, no longer load-bearing for memory safety.
