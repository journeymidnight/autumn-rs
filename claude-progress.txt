Stage 2 (this commit) — concrete changes:

  1. Wire layer (autumn-rpc/src/manager_rpc.rs):
       - POLICY_KIND_COMPACT renamed → POLICY_KIND_MAJOR_COMPACT
         (same wire value 3). Old name kept as #[deprecated] alias
         for back-compat with external consumers.
       - POLICY_KIND_MINOR_COMPACT = 5 (new) — partition-level minor
         compact debt advisory.
       - POLICY_KIND_EC = 6 (new) — per-extent EC convert advisory.
       - PartitionLoad gains 5 new fields:
           sst_tombstone_bytes, sst_expired_bytes,
           sst_out_of_range_bytes, minor_compact_pending_bytes,
           sealed_log_extent_count
         All default 0; advisory layer treats 0 as "no signal".
       Wire is backward-incompatible at rkyv level; same-commit
       upgrade for manager + PS + client (cluster.sh stops all
       roles before restart). Struct doc notes this.

  2. PS-side metric collection (partition-server):
       - PartitionMetrics gains 5 atomic counters paralleling
         PartitionLoad's new fields.
       - new helper `refresh_f202_metrics(part)` in background.rs:
           sst_expired_bytes: Σ estimated_size for tables whose
             paired SstReader.min_expires_at is non-zero & <= now.
             Conservative upper bound (whole-SST count).
           sst_out_of_range_bytes: Σ estimated_size when has_overlap
             == 1, else 0.
           minor_compact_pending_bytes: Σ estimated_size of
             pickup_tables output when has_overlap == 0.
           sst_tombstone_bytes / sealed_log_extent_count: left 0
             (require SST on-disk aggregate / cached
             get_stream_info; deferred to a future stage).
       - Refresh hook sites: every place that updates
         pending_compaction_bytes (4 sites in
         background_compact_loop) + commit_flush_outcome after
         each flush.
       - report_load_loop reads the new atomics, populates
         PartitionLoad on each 30 s pulse.

  3. Manager-side advisory generation (manager/src/policy.rs):
       - new consts: MINOR_COMPACT_PENDING_HIGH (512 MiB),
         MINOR_COMPACT_COOLDOWN_SEC (120 s — shorter than major
         because minor is cheaper), EC_MIN_EXTENT_BYTES (64 MiB —
         common-sense filter against negative-EV EC conversions
         on small extents).
       - PolicyConfig extended with three corresponding fields.
       - compute_maintenance_advisory gains a third arm for
         MINOR_COMPACT:
           gated by `minor_compact_pending_bytes >
             MINOR_COMPACT_PENDING_HIGH` sustained across
             `required_buckets`
           AND `minor_compact_pending_bytes > 0` in latest bucket
             (common-sense filter: don't suggest minor compact
             when pickup_tables had nothing to do)
           AND outside the minor cooldown.
       - new compute_ec_advisory(state, now): iterates s.streams
         + s.extents directly (EC is per-extent, not bucketed).
         Filters:
           stream has EC policy attached (ec_data_shard > 0)
           extent is sealed (sealed_length > 0)
           not already converted
           sealed_length >= ec_min_extent_bytes (common-sense)
         Emits POLICY_KIND_EC with primary_part_id=0,
         secondary_part_id=extent_id, size_bytes=sealed_length.
       - policy_tick_loop unions all 4 compute_*_advisory outputs
         into advisory_cache.

  4. Client (autumn_client.rs):
       - policy command kind mapping prints 7 strings:
         split / merge / gc / major / minor / ec / hotcold
       - feas column shows "n/a" for all maintenance/EC kinds.
