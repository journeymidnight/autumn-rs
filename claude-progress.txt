Task scope: F138 — eversion lost-update across EC conversion await.
            Manager's ec_conversion_dispatch_loop captured new_eversion
            before the EXT_MSG_CONVERT_TO_EC await; apply_ec_conversion_done
            then wrote it back unconditionally, overwriting concurrent bumps
            from apply_recovery_done / mark_extent_available / split.
            Also: apply_ec_conversion_done's ex.replicates overwrite silently
            reverted recovery slot replacements.

Root cause (confirmed via unit tests):
  • apply_ec_conversion_done wrote `ex.eversion = new_eversion` (captured
    before the await) instead of incrementing, losing any concurrent bumps.
  • apply_ec_conversion_done wrote `ex.replicates = target_nodes[..K]`
    (also captured at dispatch time), reverting recovery's node replacement.
  • The lock (ec_conversion_inflight.remove) fired BEFORE the apply, leaving
    a window between remove and apply_ec_conversion_done where the race
    remained reachable.

Fix (option b — eversion-bump lock, symmetric to F136):
  1. ec_conversion_dispatch_loop: move ec_conversion_inflight.remove to AFTER
     apply_ec_conversion_done completes (or fails). Lock now covers full
     dispatch → RPC await → in-memory+etcd apply window.
  2. apply_recovery_done (recovery.rs): check ec_conversion_inflight at
     entry; return Err::Precondition if set; keep recovery_tasks entry for
     next 2 s retry tick.
  3. recovery_dispatch_loop (recovery.rs): skip per-slot processing entirely
     when ec_conversion_inflight contains the extent, preventing re_avali
     from triggering mark_extent_available during EC.
  4. mark_extent_available (lib.rs): same check + Err early-return.
  5. handle_multi_modify_split (rpc_handlers.rs): check all source-stream
     extents; return Err::Precondition if any is locked.
