Current summary:
  DONE + verified. `drain_zc_writes` (lib.rs) runs in the ps-conn read loop
  right after decoder.feed, before normal decode:
    - If the FRONT frame is a UCX MSG_PUT_ZC with value >=
      AUTUMN_PS_ZC_RECV_MIN_BYTES (64 KiB) and <= the inline cap, and
      part_id == owner_part: peek_header + peek_payload (new FrameDecoder
      helpers) locate the value boundary WITHOUT consuming; consume header+
      meta+key; drain buffered value prefix into a PooledBuf; recv_into the
      remainder (registered RDMA on UCX). V1 payload CRC validated over
      meta||key||value via compute_payload_crc.
    - Value rides onward as Bytes::from_owner(pb) via a NEW
      PartitionRequest.zc_value: Option<Bytes>; payload carries only
      [meta][key]. enqueue_put_zc uses zc_value directly when present (no
      concat-back copy), else slices from payload as before.
    - Gated on reader.is_ucx() (TCP unchanged); small writes (< 64 KiB) keep
      the FrameDecoder path (only added cost there: one peek_header + branch).
    - d=1 fast path skipped when drain_zc_writes queued a reply
      (inflight.is_empty() guard) to preserve in-order replies.
    - Cancel-safe: drain_zc_writes owns the PooledBuf across the recv; on conn
      error / task drop, recv_into's InflightSlot drains UCX before the buffer
      returns to the pool (no leak — same rule as the read path).
    - PS_ZC_WRITE_RECV_HITS counts engagements; logged once on first engage.

  Why W1 only (not W2/EN-recv): W2 is structurally limited — EN uses buffered
  pwrite (no O_DIRECT), so recv-into-registered only saves one memcpy and breaks
  the EN batch-pwritev model. True NIC->disk DMA needs O_DIRECT + io_uring
  registered buffers (3FS model), a bigger change. PS-recv (W1) is clean: large
  value -> registered buffer -> forwarded to EN (send already rcache-ZC), value
  never enters memtable (only the VP does).
