New manager RPCs:
  - `MSG_FORCE_EC_CONVERT = 0x39` (ForceEcConvertReq /
    ForceEcConvertResp): validates extent (sealed, not
    converted, on EC stream); allocates extra parity nodes via
    the same shuffled-pool path the deleted fresh-dispatch
    used; persists rich `pending_ec_dispatch` marker; returns
    CODE_OK. Next dispatch tick drains via F198 replay.
    Idempotent.
  - `MSG_GET_PARTITION_DETAIL = 0x3A` (GetPartitionDetailReq /
    GetPartitionDetailResp): returns most recent bucket from
    `PolicyEngine.metrics[part_id]`. Sources `client info
    --detail` without a dedicated PS RPC.

New `client` subcommands:
  - `client force-ec-convert --extent <EXTID>` — sends
    MSG_FORCE_EC_CONVERT.
  - `client streams [--json]` — lists each stream's
    `extent_id / sealed_length / ec_converted / replicas /
    parity / refs / eversion`. JSON output sorted by
    stream_id; plain text mirrors layout-typed extent labels.
  - `client info --part PID --detail [--json]` — new `--detail`
    flag. Sends MSG_GET_PARTITION_DETAIL, prints full
    `PartitionLoad` including F202 fields (gc_debt_bytes,
    pending_compaction_bytes, minor_compact_pending_bytes,
    sst_tombstone_bytes, sst_expired_bytes,
    sst_out_of_range_bytes, *_inflight, last_*_at,
    sealed_log_extent_count).

policy controller binary on top, or wire MSG_GET_POLICY_CANDIDATES
