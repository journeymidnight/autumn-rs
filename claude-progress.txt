Summary:
  Replaces the pre-F214 fork between `autumn-op format` / `autumn-op
  register-node` / `autumn-extent-node --disk-id` with a single
  Ceph-mkfs-style flow: manager imprints a cluster_id on first
  leader-promotion → `autumn-op format` queries it and stamps each
  formatted dir → `autumn-extent-node` refuses to start without the
  sentinel files and cross-checks the stamped cluster_id against
  the manager.

  Per user pushback during planning, the post-format node state is
  a proper state machine variant (`NodeAutoState::Suspend`) rather
  than overloading `disk.online=false`. `select_nodes` gates fresh
  extent allocation on `Online` state — Suspend nodes don't get
  traffic until the manager's 10 s `disk_status_update_loop` verifies
  them via df.

Behaviour notes / forward-looking rule:
  - cluster_id is the single source of truth for "which cluster does
    this disk belong to". A future operator misconfiguration (point
    EN at wrong manager) is now caught at startup with both UUIDs
    in the error.
  - Suspend → Online transition takes 10-20 s (one disk_status_update_loop
    cycle + soft-timeout debounce). Bootstrap's cold-leader fallback
    in select_nodes preserves the existing "no df sweep yet" path.
  - Re-running `autumn-op format` against a dir with matching
    cluster_id is idempotent — reuses the stored disk_uuid so the
    manager's re-register branch returns the same disk_id. This is
    the safety net for "manager lost in-memory state in no-etcd mode"
    in do_start_node's restart path.
  - autumn-stream-cli's `register-node` subcommand was NOT touched
    (low-level debugging CLI; the MSG_REGISTER_NODE wire RPC stays).
  - The pre-existing autumn-stream test compile errors
    (`WriteShardReq.revision` missing — from F211-D landing) are
    UNRELATED to F214 and pre-date this PR.
