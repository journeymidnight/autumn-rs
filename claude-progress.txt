Work this iteration:
  1. Reviewed all F129 sites — confirmed server handlers, recovery, GC
     skip path for OP_CHUNK_BLOB, multi-frag VP read path, and client
     SDK (PutStreamHandle / GetStream) were complete.
  2. Considered + rejected put_auto / get_auto convenience helpers.
     Rationale: put_auto would silently route a buffered Vec<u8>
     through streaming with no memory-profile change but masks the
     "you crossed a code-path boundary" signal. get_auto would buffer
     N×4 MiB chunks back into one Vec<u8>, defeating streaming's
     entire purpose. Callers know their value class — clean error
     from `put` on > 64 MiB is the right interface.
  3. New integration test: crates/manager/tests/system_putstream.rs
     covering 12 MiB roundtrip (4×3 MiB chunks, exercises uneven
     fragments + cross-fragment sub-range reads), single-chunk 1 MiB
     edge case (n_frags=1 mfvp distinct from legacy single-VP), and
     abort path (session dropped, get returns None).
  4. README.md "Large value" section now distinguishes inline VP
     (>4 KiB) from F129 multipart (>64 MiB), with a 200 MiB putstream
     /getstream example.
  5. feature_list.md F129: passes:false → true. Top-of-file Completed

Wire / handler / SDK summary (already shipped pre-this-iteration):
  - Wire types: MSG_PUT_BEGIN=0x49, MSG_PUT_CHUNK=0x4A,
    MSG_PUT_COMMIT=0x4B, MSG_PUT_ABORT=0x4C; PutBegin/Chunk/Commit/Abort
    Req+Resp shapes. Inline cap = AUTUMN_PS_MAX_INLINE_BYTES_DEFAULT
    (64 MiB), hard ceiling 256 MiB. Op flag distinguishes single-VP
    from multi-VP: OP_VALUE_POINTER=0x80, OP_VALUE_POINTER_MULTI=0x40,
    OP_CHUNK_BLOB=0x10. CODE_VALUE_TOO_LARGE=5, CODE_UPLOAD_NOT_FOUND=6.
  - Server: handle_put_begin/chunk/commit/abort. Sessions held in
    PartitionData.upload_sessions: HashMap<u128, UploadSession> with
    AUTUMN_PS_MAX_UPLOAD_SESSIONS_DEFAULT=1024 cap and
    AUTUMN_PS_UPLOAD_TTL_SECS_DEFAULT=30min idle TTL.
  - Read path: handle_get / handle_head decode OP_VALUE_POINTER_MULTI;
    resolve_value dispatches to resolve_multi_frag (sequential per-
    fragment reads, F131 will add concurrency).
  - Recovery: WAL replay skips OP_CHUNK_BLOB; OP_VALUE_POINTER_MULTI
    re-inserts the encoded mfvp blob into memtable (preserved across
    restart).
  - Client SDK: ClusterClient.put_stream_begin → PutStreamHandle
    {send, commit, abort}; ClusterClient.get_stream → GetStream
    {next_chunk, total_bytes, position, remaining}.
  - CLI: autumn-client putstream <KEY> <FILE> [--chunk-size N];
    autumn-client getstream <KEY> [--chunk-size N] [--out FILE].
