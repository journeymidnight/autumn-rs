TaskStatus: completed
Task scope: F149 — Leader-fence on every manager etcd write txn. Closes the
            failover-gap split-brain window where a deposed leader's in-process
            `self.leader.get() == true` flag could lag etcd ground truth and
            allow last-writer-wins overwrites of the new leader's mirror_*
            state.

Why F149 was needed:

  F005's lease-based leader election (10 s lease + 2 s keepalive + create_revision
  CAS) is sufficient to guarantee that at most one manager **holds** the leader-key
  at any time. It is NOT sufficient to prevent a deposed leader from issuing etcd
  writes that overwrite the new leader's state. The window between (a) the etcd
  lease expiring + a new leader winning the CAS, and (b) the old leader's
  keepalive task observing failure and flipping `set_leader(false)` is bounded
  by lease TTL + keepalive jitter on a healthy host (~10 s), but unbounded under
  compio runtime starvation, GC pauses, or syscall hangs. During that window
  the deposed leader's mirror_* paths (which use plain etcd puts, not version-
  conditional CAS) can revert recovery slot replacements, EC conversion eversion
  bumps, partition splits, etc.

Fix shipped (F149):

  Added Cmp::value() helper to autumn-etcd (target=3 VALUE, result=0 EQUAL).

  Made `EtcdMirror` carry `instance_id: Rc<String>` + `leader: Rc<Cell<bool>>`
  (shared with AutumnManager).

  Added a private `EtcdMirror::txn_fenced(extra_cmp, success, failure)` that
  always prepends `Cmp::value(LEADER_KEY) == instance_id` to extra_cmp. On
  txn rejection it does a follow-up GET on the leader-key to distinguish
  fence-fail (flip `leader` Cell to false, return AppError::NotLeader) from
  extra_cmp-fail (return Ok(false), preserving the create_revision==0
  semantics for owner-lock + recoveryTasks acquisition).

  Rerouted `put_msgs_txn` and `put_and_delete_txn` through `txn_fenced(vec![],
  …)`. Return type changed from `anyhow::Result<()>` to `Result<(), AppError>`
  so the NotLeader distinction propagates without translation.

  Five callsite groups now go through the fence:
    1. All 9 `mirror_*` helpers (lib.rs ~1218–1431) — `.map_err(...)` shims
       stripped now that the helpers return AppError directly.
    2. `persist_extent` (lib.rs ~1217).
    3. `acquire_owner_revision` (lib.rs ~665) — extra_cmp = create_revision==0
       on `ownerLocks/$owner_key`. The follow-up GET reads the existing
       revision when the CAS fails.
    4. `dispatch_recovery_task` (recovery.rs ~107) — extra_cmp =
       create_revision==0 on `recoveryTasks/$extent_id`. Returns Ok(()) on
       Ok(false) (already in-flight), bubbles NotLeader on Err.
    5. `handle_multi_modify_split` Phase-2 consolidated txn (rpc_handlers.rs
       ~1533) — error mapper updated to `Self::err_to_status` so NotLeader
       maps to StatusCode::Unavailable instead of being flattened to Internal.

  Intentionally NOT routed through txn_fenced:
    - `try_become_leader` — the txn IS the operation establishing ownership of
      the leader-key; cannot fence on a key we are about to acquire.
    - `replay_from_etcd` — read-only, no fence semantics.
    - `leader_keepalive_loop` — pure lease keep-alive, no k/v write.

Distributed-systems audit:

  1. Identity — instance_id is generated by `uuid::Uuid::new_v4()` once at
     `AutumnManager::new()`. It survives the entire process lifetime and is the
     same value written into LEADER_KEY by `try_become_leader` AND used by
     `txn_fenced` as the fence operand. The same instance can re-acquire
     leadership after a transient failure (its previous lease expired, the
     LEADER_KEY auto-deleted, the next election round wrote the same
     instance_id back) — fence still works because we are comparing against
     ourselves.

  2. The follow-up GET in txn_fenced on rejection: there is a brief race where
     between the failed txn and the GET, the new leader could itself be
     deposed and a third leader could win — but in that scenario the GET sees
     the third leader's instance_id, which still doesn't match ours, so we
     correctly return NotLeader. The only way the GET returns "still leader"
     after a txn fail is if the extra_cmp itself failed — which is the
     intended Ok(false) path.

  3. The leader Cell flip is monotonic-during-deposition: once flipped to
     false, only `try_become_leader` can flip it back to true, and only
     after a successful CAS that re-establishes ownership. So the
     "false-flip-then-instantly-true" race is impossible.
